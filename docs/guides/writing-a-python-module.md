# Writing a Python module

**Status:** living guide
**Last verified:** 2026-08-20
**Example:** [examples/modules/hello-py/](../../examples/modules/hello-py/)

This is a minimal process module. It uses the standard library only, with
no pip install needed. A user presses a pad, the screen shows which one,
and the pad lights green.

Shared protocol: [writing-a-process-module.md](writing-a-process-module.md).

## Install and run

```bash
go run ./cmd/pushapp -install examples/modules/hello-py
go run ./cmd/pushapp -module hello-py
```

This requires `python3` on PATH. If your system uses a different
interpreter name, edit `exec` in `manifest.json`.

## manifest.json

```json
{
  "id": "hello-py",
  "name": "Hello (Python example)",
  "version": "1.0.0",
  "author": "push-tethered-app examples",
  "needs_midi_out": false,
  "exec": "python3 run.py"
}
```

Set `"needs_midi_out": true` only if you call `send_cc` or `send_note`.

## Structure of run.py

1. Read stdin line by line. Each line is one JSON envelope.
2. Dispatch on `method`: `init`, `handle`, `draw`, or `close`.
3. Respond to requests that include an `id`. Do not respond to
   notifications.
4. Notify the host with `set_pad` or `set_button`. These carry no `id`.

See [run.py](../../examples/modules/hello-py/run.py) for the full listing.

## Flush stdout — required

```python
def send(obj):
    sys.stdout.write(json.dumps(obj) + "\n")
    sys.stdout.flush()  # NOT optional
```

Python buffers stdout when it connects to a pipe. If you omit the flush,
the host waits forever for the first `draw` response.

## Pad events

`handle` sends this:

```json
{"method": "handle", "params": {"kind": "pad", "data": {"note": 36, "pressed": true, "col": 0, "row": 0}}}
```

Light a pad with a palette index, not RGB:

```python
notify("set_pad", {"note": note, "colour": 11})  # 11 = green
notify("set_pad", {"note": note, "colour": 0})   # off
```

Palette reference: [hardware-reference.md](../hardware-reference.md), and
the upstream
[push3-led-colors.md](https://github.com/federico-pepe/ableton-push-hack/blob/main/docs/push3-led-colors.md).

## Draw response

```python
def draw(state):
    ops = [
        {"kind": "rect", "params": {"x": 0, "y": 0, "w": 960, "h": 160,
         "c": {"R": 0, "G": 0, "B": 0, "A": 255}}},
        {"kind": "text", "params": {"x": 8, "baseline": 80, "s": "press a pad",
         "c": {"R": 255, "G": 255, "B": 255, "A": 255}}},
    ]
    return {"ops": ops, "failed": 0}
```

Screen colors are RGBA dicts. Pad LED colors are separate palette indices.
Do not hand-copy RGB values for a screen color. Instead, load
`palette.json` (generated by `cmd/genpalette`, and stored next to
`run.py`) and look up a color by name, or by the same 0-127 index that
`set_pad` uses. See
[writing-a-process-module.md](writing-a-process-module.md#colors).

## Close

Clear any lit pads before you respond to `close`:

```python
elif method == "close":
    if state.lit_note is not None:
        notify("set_pad", {"note": state.lit_note, "colour": 0})
    respond(id_, {})
    break
```

## Debugging

- Run with `-module hello-py` and watch host stderr for protocol errors.
- The host forwards child stderr to the host log unparsed. Use it for your
  own print statements.
- If nothing appears on screen, suspect a missing flush first.
